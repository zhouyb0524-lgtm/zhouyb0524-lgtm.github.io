# AI 销售训练系统 产品需求文档

版本：v1.0 评审稿  
日期：2026-10-26  
作者：周玉冰（需求材料由本人提供，本文据现有资料整理）  
用途：项目复盘、产品方案评审及后续开发拆解。本文描述目标需求，不等于全部功能已上线。

## 1. 背景与问题

门店销售需要理解产品资料，也需要在真实对话中完成需求挖掘、卖点解释和异议处理。单独阅读产品资料难以暴露对话能力缺口，线下陪练又依赖带教人员。产品连接产品学习、销售 SOP 与模拟客户练习。

## 2. 依据与当前边界

用户提供了产品目录与详情、学习 SOP、产品资料、30 秒成交卡入口，以及 AI 客户对话和阶段反馈截图。客户画像配置、训练记录、完整评分维度和管理后台尚未提供验证材料，以下作为需求设计。

## 3. 目标用户与任务

| 用户 | 使用任务 | 期望结果 |
| --- | --- | --- |
| 门店销售 | 学习产品并进行场景对话 | 知道如何介绍产品及改进沟通 |
| 销售带教或店长 | 布置训练、查看薄弱环节 | 获得可解释的练习反馈 |
| 产品资料管理员 | 更新价格、规格和话术 | 保证训练使用有效产品资料 |

## 4. 产品目标与范围

围绕单一产品品类提供产品学习和文字对话训练，覆盖破冰、需求挖掘、产品推荐、异议处理及下一步推进；反馈首先服务于练习改进。

**首版范围外：**首版不承诺训练分数能预测成交业绩；不自动对真实客户发送话术；语音评测、情绪识别及员工绩效排名不纳入首版。

优先级：P0 为首版必须闭环；P1 在 P0 质量通过后实施。具体工期需结合接口、数据与资源评估。

## 5. 核心用户流程

选择产品 → 阅读资料与 SOP → 查看成交卡 → 选择客户场景 → AI 扮演客户 → 销售回复 → 按阶段检查覆盖点 → 完成或结束练习 → 查看反馈与证据 → 针对薄弱环节重练。

## 6. 功能需求

| 编号 | 功能 | 优先级 | 行为与约束 | 验收要点 |
| --- | --- | --- | --- | --- |
| 02-01 | 产品目录与资料 | P0 | 按品类与系列浏览，支持关键词搜索；详情展示型号、适用人群、价格口径、功能卖点与导购讲解。 | 目录与详情使用同一版本资料；价格展示生效日期与参考性质，缺失字段不得编造。 |
| 02-02 | SOP 与成交卡 | P0 | 按销售阶段展示目标、必要问题和推荐表达；成交卡提炼核心卖点、适用场景及常见异议。 | 内容关联产品版本；没有依据的优惠与性能承诺不得出现。 |
| 02-03 | 模拟客户 | P0 | 用户选择产品和预置客户场景，系统按画像、预算和装修阶段进行文字对话。 | 客户回答遵守场景设定；不因销售未提问就直接暴露所有需求。 |
| 02-04 | 阶段反馈 | P0 | 逐阶段检查沟通要点，区分已覆盖、未覆盖和不适用；反馈引用销售的具体表达并给出改进建议。 | 漏掉一个要点不自动判定整段对话失败；反馈能定位对应消息。 |
| 02-05 | 练习总结与重练 | P0 | 用户结束后查看阶段结果、关键问题和下一次练习建议；支持重开同场景。 | 未完成练习标明中途结束，不混入完整练习成绩。 |
| 02-06 | 训练管理 | P1 | 带教人员配置练习任务并查看授权范围内的完成情况与常见缺口。 | 员工只能查看自己的记录，管理员查看范围由组织权限决定。 |

## 7. 业务规则

1. 客户角色与评分角色使用分开的指令及结构化输出，避免客户直接泄露参考答案。
2. 阶段推进依据配置的关键条件；截图中的破冰阶段允许“主动问候已覆盖、明确产品未覆盖”仍进入下一阶段，具体权重由业务负责人确认。
3. 反馈区分沟通方式问题和产品事实错误；事实判断以有效资料为准。
4. 用户要求跳出客户角色、修改评分或虚构优惠时，训练保持场景约束。

## 8. 信息与状态设计

**核心对象：**Product：型号、系列、规格、参考价格、有效版本；SOP：阶段、目标、必问项、推进条件；Scenario：客户画像、预算、需求、异议；Session：用户、产品版本、场景、消息、阶段、结束状态；Feedback：维度、结果、引用消息、建议、评估版本。

**状态流转：**训练：未开始 → 进行中 → 已完成／用户结束／异常中断；阶段：未进入 → 练习中 → 已检查 → 可重练；资料：草稿 → 审核通过 → 发布 → 归档。

界面应区分加载、空数据、失败、部分成功和完成状态。成功提示必须来自对应数据写入或服务结果，不能只根据按钮点击生成。

## 9. 异常处理

| 场景 | 处理要求 |
| --- | --- |
| 产品资料缺失或过期 | 提示资料状态并阻止基于未知参数进行事实评分 |
| 对话生成超时 | 保留已输入内容与历史消息，支持重试，不重复保存同一轮 |
| 反馈无法关联原文 | 不展示确定性结论，标记反馈待复核 |
| 用户刷新或退出 | 保存已确认消息，恢复时继续原训练或明确新建训练 |

## 10. 质量与数据要求

- 访问与隔离：服务端或扩展本地按实际身份与权限控制数据；会话、任务和用户之间不得串数据。
- 可靠性：为操作保留稳定标识与版本；重试、刷新和恢复不重复创建核心记录；失败原因可定位。
- 性能：先记录代表性数据规模下的加载、任务耗时及失败分布，再确定容量与响应预算；不虚构性能承诺。
- 可用性：主要操作可用键盘完成，颜色之外提供文字状态；表格在窄屏可横向滚动，不能截断关键操作。
- 可追溯性：记录请求或任务 ID、数据与规则版本、关键状态变化及脱敏错误；不在日志保存密钥或不必要的敏感正文。
- 数据生命周期：提供按权限查看、删除或归档的能力；实际保留期限、备份和恢复策略在上线前确认。

## 11. 指标与评测

训练完成率 = 完整完成会话数 / 开始训练会话数；反馈证据有效率 = 引用存在且支持判断的反馈数 / 抽检反馈数；人工一致率按同一标注准则比较带教与系统判断；重复练习观察同场景关键要点覆盖率变化。首轮建立基线后再确定目标值，不将对话轮数或分数直接等同于销售能力提升。

指标评测应记录：数据来源、样本数、标注准则、版本、运行环境、测试日期、分子分母及失败案例。业务效果与系统测试结果分开报告。

## 12. 验收场景

- [ ] AC-01：搜索型号后能进入对应详情，成交卡与详情使用相同产品版本。
- [ ] AC-02：模拟客户能在销售询问家庭人数或装修阶段后给出符合场景的回答。
- [ ] AC-03：阶段反馈显示已覆盖与未覆盖项，并引用可定位的销售消息。
- [ ] AC-04：产品资料没有优惠信息时，系统不能建议销售承诺不存在的折扣。
- [ ] AC-05：中途退出与完整完成分别记录；重练不会覆盖原始练习。

## 13. 迭代与发布条件

1. 需求与数据确认：确认用户、支持范围、资料权限、依赖接口与未决问题；确定首版 P0。
2. 方案与原型：走通正常、异常及恢复流程；业务方核对术语、状态与关键规则。
3. 端到端实现：优先完成一条可验证主链路，再扩展场景；记录模拟与真实依赖的差别。
4. 试用验收：按上述场景逐条保留结果，修复阻断问题，再组织受控试用。
5. 复盘迭代：根据失败分类和用户反馈安排 P1，更新文档版本与交付状态。

发布前至少满足：P0 验收通过；访问与数据隔离通过；关键失败可恢复；已知限制可见；交付文档说明实际验证范围。

## 14. 待确认事项

- 哪些产品资料可公开、哪些价格与卖点需要定期审核。
- 阶段推进条件、反馈权重和专家标注标准。
- 训练记录保留期限、组织权限和是否需要语音输入。
