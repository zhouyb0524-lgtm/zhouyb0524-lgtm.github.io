# 电商商品评价洞察与运营分析平台 产品需求文档

版本：v1.0 评审稿  
日期：2026-10-26  
作者：周玉冰（需求材料由本人提供，本文据现有资料整理）  
用途：项目复盘、产品方案评审及后续开发拆解。本文描述目标需求，不等于全部功能已上线。

## 1. 背景与问题

商品评价包含多个主题和混合情感，人工归类耗时，单纯好评率又难以指导改进。产品将清洗、主题分类、方面级情感、原文证据和报告组织为一条可追溯的分析流程。

## 2. 依据与当前边界

功能依据用户简历整理；作品集中的“评见”是本次制作的原创前端原型。评价数、占比、评价文本及建议均为示例，不代表真实分析结果；当前页面未连接上传处理、模型批处理或数据库。

## 3. 目标用户与任务

| 用户 | 使用任务 | 期望结果 |
| --- | --- | --- |
| 电商运营 | 定位商品常见问题和变化 | 形成有证据的运营行动 |
| 产品与品控人员 | 按 SKU 查看反馈 | 区分产品、安装、物流等问题 |
| 分析负责人 | 维护标签及评测口径 | 让批次结果可比较、可复核 |

## 4. 产品目标与范围

首版支持文件导入、SKU 关联、多主题与方面级情感、证据回溯、批次恢复及报告导出；数据来自用户授权文件。

**首版范围外：**不自动抓取第三方平台、不声称推断结果代表全部消费者、不用模型自由生成统计数量。自动修改商品页或发起营销活动不在首版。

优先级：P0 为首版必须闭环；P1 在 P0 质量通过后实施。具体工期需结合接口、数据与资源评估。

## 5. 核心用户流程

上传 CSV 或 Excel → 映射字段 → 校验并预览 → 确认清洗规则 → 创建分析批次 → 多标签与情感识别 → 校验证据 → 聚合统计 → 主题筛选与原文复核 → 生成报告 → 失败记录修复后重跑。

## 6. 功能需求

| 编号 | 功能 | 优先级 | 行为与约束 | 验收要点 |
| --- | --- | --- | --- | --- |
| 05-01 | 导入与字段映射 | P0 | 上传支持格式文件，映射评价 ID、正文、SKU、评分和时间；预览缺失、重复及无效值。 | 正文为空的记录隔离并显示原因；未确认映射前不启动模型分析。 |
| 05-02 | 清洗与去重 | P0 | 记录源文件行号与原文，按明确规则检查 ID 重复、重复正文及 SKU 缺失。 | 去重规则和被排除行可查看；相同正文但不同真实评价不能默认全部删除。 |
| 05-03 | 多标签与方面级情感 | P0 | 按版本化标签体系识别单条评价的多个主题，对各主题分别标注正向、负向、中性或无法判定。 | “安装方便但包装破损”同时保留安装正向和包装负向，不强压成一个总体标签。 |
| 05-04 | 证据校验 | P0 | 标签关联原文片段并验证确实存在，保留评价与来源位置。 | 不存在或不支持判断的证据不能进入可信报告；允许人工修正并留版本。 |
| 05-05 | 统计与筛选 | P0 | 由代码计算主题计数、提及率和 SKU 聚合；按主题、情感、商品及批次查看明细。 | 展示分母和有效样本数；筛选后统计与明细使用相同口径。 |
| 05-06 | 批次与失败恢复 | P0 | 任务 ID 关联记录状态，对超时、格式错误与遗漏条目执行有限重试。 | 重复启动不重复计费分析成功条目；终止后能从失败或未完成记录恢复。 |
| 05-07 | 运营报告 | P1 | 报告包含数据范围、统计结果、典型证据、建议和限制；支持导出。 | 每项主要结论有数据或原文支持，建议与事实分开呈现。 |

## 7. 业务规则

1. 主题提及率 = 提及该主题的去重有效评价数 / 当前筛选范围内去重有效评价数；一条评价可计入多个主题，因此主题占比之和可超过 100%。
2. 某主题负向占比以提及该主题的有效评价为分母，不能与总体负面评价占比混用。
3. 无时间或无 SKU 的记录单独归类；不得默默补造日期或归属商品。
4. 同一模型与标签版本的相同输入可复用，标签体系改变后需重新计算并保留旧结果。
5. 报告生成只读取已完成且通过校验的统计和证据；失败记录数量必须显式展示。

## 8. 信息与状态设计

**核心对象：**Import：文件、字段映射、导入时间；Review：源行、原文、评价 ID、SKU、时间；LabelVersion：标签定义与版本；Analysis：模型版本、各主题情感、证据及校验状态；Batch：任务 ID、成功/失败/跳过数、成本估计、状态；Report：筛选条件、分母、结果版本、导出时间。

**状态流转：**批次：待校验 → 待确认 → 排队中 → 分析中 → 完成／部分失败／已取消／失败；记录：待分析 → 处理中 → 成功／证据不合格／失败／跳过。取消停止新任务，已完成结果保留。

界面应区分加载、空数据、失败、部分成功和完成状态。成功提示必须来自对应数据写入或服务结果，不能只根据按钮点击生成。

## 9. 异常处理

| 场景 | 处理要求 |
| --- | --- |
| 字段缺失或文件不受支持 | 显示问题列与样例行，允许重新映射或换文件 |
| 模型输出结构无效 | Pydantic 校验失败后按有限重试策略处理，失败隔离 |
| 证据不是原文或缺少记录 | 标记待复核，不填补虚构片段，也不假报整批完成 |
| 限流、断网或页面关闭 | 服务端保存任务状态，重新进入可查看或恢复 |
| 样本过少或筛选为空 | 展示样本限制或空态，不输出确定性趋势结论 |

## 10. 质量与数据要求

- 访问与隔离：服务端或扩展本地按实际身份与权限控制数据；会话、任务和用户之间不得串数据。
- 可靠性：为操作保留稳定标识与版本；重试、刷新和恢复不重复创建核心记录；失败原因可定位。
- 性能：先记录代表性数据规模下的加载、任务耗时及失败分布，再确定容量与响应预算；不虚构性能承诺。
- 可用性：主要操作可用键盘完成，颜色之外提供文字状态；表格在窄屏可横向滚动，不能截断关键操作。
- 可追溯性：记录请求或任务 ID、数据与规则版本、关键状态变化及脱敏错误；不在日志保存密钥或不必要的敏感正文。
- 数据生命周期：提供按权限查看、删除或归档的能力；实际保留期限、备份和恢复策略在上线前确认。

## 11. 指标与评测

按主题计算多标签 Precision、Recall、F1，并报告宏平均与微平均、各标签样本量；用独立人工标注集对比关键词基线与模型方案，避免训练与评测数据泄漏；证据有效率按来源存在及支持结论分别统计；另观察成功率、单位评价耗时与成本。当前没有可核实结果数值，首轮评测后再设业务目标。

指标评测应记录：数据来源、样本数、标注准则、版本、运行环境、测试日期、分子分母及失败案例。业务效果与系统测试结果分开报告。

## 12. 验收场景

- [ ] AC-01：给定包含重复、空文本和缺 SKU 的小样本，预览数量与处理原因准确可核对。
- [ ] AC-02：混合情感评价保留多个主题与各自情感，证据全部能定位到原文。
- [ ] AC-03：对人工可手算样本，主题计数与提及率等于预期结果，并展示明确分母。
- [ ] AC-04：筛选负向主题后明细与统计一致，点击原文能查看完整文本与标签证据。
- [ ] AC-05：中断再恢复只处理未完成或失败记录，结果不重复累加。
- [ ] AC-06：导出报告包含筛选条件、样本量、失败数、版本和证据；不把示例数据写成真实成果。

## 13. 迭代与发布条件

1. 需求与数据确认：确认用户、支持范围、资料权限、依赖接口与未决问题；确定首版 P0。
2. 方案与原型：走通正常、异常及恢复流程；业务方核对术语、状态与关键规则。
3. 端到端实现：优先完成一条可验证主链路，再扩展场景；记录模拟与真实依赖的差别。
4. 试用验收：按上述场景逐条保留结果，修复阻断问题，再组织受控试用。
5. 复盘迭代：根据失败分类和用户反馈安排 P1，更新文档版本与交付状态。

发布前至少满足：P0 验收通过；访问与数据隔离通过；关键失败可恢复；已知限制可见；交付文档说明实际验证范围。

## 14. 待确认事项

- 首批数据文件、授权范围、字段与真实去重规则。
- 标签体系由谁维护，人工标注分歧如何裁决。
- 支持的单文件大小、批次容量、重试次数和费用预算需通过样本压测确定。
